# Pumping Iron

Личное веб-приложение для тренировок: программа на три дня, журнал подходов, замеры тела и фото прогресса, статистика, рацион и дневник питания, медитации и ИИ-тренер, который видит все эти данные и умеет добавлять упражнения и продукты. Интерфейс на русском. Данные хранятся локально в файле SQLite, облако не нужно.

Стек: Python 3.14, FastAPI, Jinja2, SQLite, менеджер пакетов [uv](https://docs.astral.sh/uv/). ИИ-тренер работает через локальную модель в [LM Studio](https://lmstudio.ai/) или, по желанию, через Claude API.

## Установка

Нужна Windows, [Git](https://git-scm.com/download/win) и uv. Python 3.14 ставить отдельно не надо: uv скачает его сам.

1. Установите uv (в PowerShell):

   ```powershell
   winget install --id=astral-sh.uv -e
   ```

   Другие способы установки описаны в [документации uv](https://docs.astral.sh/uv/getting-started/installation/). После установки откройте новое окно терминала.

2. Скачайте проект:

   ```powershell
   git clone https://github.com/BorodaPetra/Pumping_Iron.git
   cd Pumping_Iron
   ```

   Без Git можно скачать архив: зелёная кнопка **Code → Download ZIP** на странице репозитория, затем распаковать.

Зависимости ставить вручную не нужно: при первом запуске uv сам создаст виртуальное окружение и установит всё из `pyproject.toml`.

## Запуск

Дважды щёлкните `start.bat` в папке проекта. Он запускает сервер и через 3 секунды открывает http://127.0.0.1:8000 в браузере. Первый старт дольше обычного (uv ставит зависимости). Если страница не открылась сразу, подождите несколько секунд и обновите её. Окно с сервером нужно держать открытым, закрытие окна останавливает приложение.

Или то же самое из терминала:

```powershell
uv run pumping-iron
```

При первом запуске создаётся база `data/pumping_iron.db` с готовым справочником из 121 упражнения; при следующих запусках схема обновляется сама, данные не теряются. Папка `data/` не попадает в git, там лежат ваши данные и фото. Чтобы работать с другой базой, задайте путь в переменной окружения `PUMPING_IRON_DB`.

## ИИ-тренер: локальная модель в LM Studio

Всё, кроме вкладки «АИ тренер», работает без модели. Чтобы тренер отвечал, нужен запущенный локальный сервер LM Studio.

1. Скачайте и установите [LM Studio](https://lmstudio.ai/).
2. Во вкладке **Discover** (поиск моделей) скачайте модель. Нужна модель с поддержкой вызова инструментов (tool use): без неё тренер сможет только отвечать текстом и не сможет добавлять упражнения и продукты. Для проекта проверена `qwen/qwen3.5-9b`; модель такого размера занимает порядка 6 ГБ на диске и помещается в память обычного ПК с видеокартой или без неё (без видеокарты отвечает медленнее). Модели побольше умнее, но требуют больше памяти.
3. Загрузите модель: вкладка **Chat** (или **Developer**) → выбрать модель → **Load**. Длинный контекст нужен, потому что тренеру передаются справочник упражнений, программа, рацион и журнал (около 10 тысяч символов), поэтому не ставьте контекст меньше 8–16 тысяч токенов.
4. Запустите локальный сервер: вкладка **Developer** → переключатель **Status: Running**. По умолчанию он слушает `http://localhost:1234`.
5. Откройте в приложении «АИ тренер» и убедитесь, что выбрано «Локальная (LM Studio)» (это вариант по умолчанию).

Если у вас другой адрес сервера или имя модели, задайте переменные окружения до запуска приложения:

| Переменная | Назначение | По умолчанию |
|---|---|---|
| `LMSTUDIO_URL` | адрес сервера LM Studio | `http://localhost:1234/v1` |
| `LMSTUDIO_MODEL` | идентификатор модели, как он показан в LM Studio | `local-model` |

Постоянно сохранить значения можно командой (потом откройте новое окно терминала и запускайте `start.bat` заново):

```powershell
setx LMSTUDIO_MODEL "qwen/qwen3.5-9b"
```

Модель небольшая и иногда пропускает пункты в длинных списках или говорит, что добавила упражнение, не вызвав инструмент. Проверяйте результат на вкладках «Тренировки» и «Питание».

## ИИ-тренер: Claude (необязательно)

Вместо локальной модели можно использовать Claude API. Задайте ключ до запуска:

```powershell
setx ANTHROPIC_API_KEY "ваш-ключ"
```

Модель по умолчанию `claude-opus-5-5`, её можно сменить переменной `ANTHROPIC_MODEL`. Запросы к API платные и идут через интернет: в Anthropic уходят текст вашего сообщения и данные тренировок, рациона и замеров из контекста. Без ключа вариант Claude в интерфейсе недоступен. Переменные окружения подхватываются только при запуске, после смены ключа сервер нужно перезапустить.

## Структура

- `src/pumping_iron/` — код приложения (`main.py` и разделы: `workouts.py`, `body.py`, `nutrition.py`, `assistant.py` и другие), `templates/` (Jinja2), `static/` (CSS, JS, картинки).
- `data/` — база и фото (только локально, в git не попадает).
- `start.bat` — запуск двойным щелчком.
